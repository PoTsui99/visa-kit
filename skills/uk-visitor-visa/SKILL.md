# 英国访客签证助手

把一次申请推进到用户授权的完成点。使用用户当前语言，优先从已授权材料提取信息，再集中询问缺失内容；不要每遇到一个页面就问一题。

## 先确定范围和当前状态

- 确认申请类别、申请地、预计行程、几位申请人、已有材料目录，以及需要做到材料准备、填表、提交、预约还是上传。
- 按 [官方来源](references/official-sources.md) 查询本次现行规定。费用、签证期限优惠、上传限制、签证中心地址、eVisa 和处理时间均须现场核对，不把旧申请的结果套给别人。
- 已有申请时先找申请编号、付款与预约记录，接着办理。不得因结果页报错就创建第二份申请、重复付款或重复预约。
- 非旅游/探亲、未成年人、赞助、自雇、在读、既往拒签等情况保留分支，不把“在职成年自费旅游”当作所有申请人的事实。

## 尽量一次收集完整答案

将 [一次性问卷](assets/Applicant_Questionnaire.md) 复制到本次申请工作目录，预填材料中能可靠读取的事实并标注来源；个人信息栏没有可靠依据就留空。只向用户发送缺失问题和冲突项，可让其一次回复编号答案或填写整份问卷。

- 每题显示“处理默认”或“无默认，需本人提供/核实”。
- 旅游、普通服务、免费自行上传等只是建议设置，需与本次委托范围及用户偏好一致。
- 安全品行题提供常见拟答“否，待本人逐项确认”。明确列出每题完整范围，让用户一次明确确认列出的整组题目，或指出例外。沉默、未勾选、以前没提过都不是确认。
- 不默认婚姻、住所、收入、储蓄、国籍、父母、出境史、犯罪/处罚/拒签经历或其他个人事实。护照空白不代表无港澳台旅行经历。
- 不把极端主义题缩写成“是否伤害过英国军人”；相关问题可能问的是支持或发表呼吁杀害的言论。以当前表格问题和帮助文字为准。
- 一次确认后持续复用，不重复提问。新出现的问题、含义变化、相互矛盾或确实缺失的事实才集中追问；可同时继续不依赖答案的材料工作。
- 将答案记为已确认、材料提取待确认、未回答、冲突；只提交已核实的事实。网页上的新问题不能按相似题目的答案自动类推。

## 整理、翻译并核对材料

处理材料时阅读 [材料与翻译](references/documents.md)，用现有 PDF/文档工具完成清晰度、数值、页序和文件限制检查。优先使用已存在的 PDF 技能；没有时采用本地 PDF 库和渲染器。

- 中文支持材料如提交，准备完整英文或威尔士文译文及可独立核验的译者声明。不得只译表头后宣称全文已翻译。
- 金融材料区分流水、资产、基金、股票和信用卡；区分总金融资产、可自由使用的储蓄和本次旅行预算，避免重复加总。银行末笔活期余额不能替代未证明的投资资产。
- 需要核对工资、大额收支或制作资金说明时，读 [流水审阅与资金说明](references/financial-review.md)。先批量核实真实来源，再制作可追溯的标注副本；标注不是默认必交要求。
- 拟用余额宝等产品时简短说明产品性质、平台及证明时点；不能把基金写成保本存款。
- 解释信用卡明细与储蓄账户流水的区别，按当前官方材料指引判断用途；发现用户误认文件类型时先说明，再决定是否补充。
- 姓名、证件号码、日期、钱款和页数进行一致性核对；公司证明假期与行程不一致时列出差异，不能改写盖章原件来消除差异。
- 真人承担译文核对责任。不要用模型名称代替译者，不编造资质、签名、核对完成或认证。申请人自行署名的可接受性须核实，不能保证。
- 只有用户明确授权才使用其签名图片；背景处理仅保留真实笔迹。正式签名不使用生成式重绘。官方材料清单若要求现场签名，始终留白。

## 在线申请、预约、上传

开始网站操作时阅读 [网站流程与故障处理](references/browser-workflow.md)。遵守当前环境浏览器工具的授权和操作规则，不以本技能扩张权限。

从已确认答案连续填写，保存可恢复的进度。遇到必填未知项可以停在该页，同时批量询问后续可预见的缺项；不要猜填后继续。

- 法律声明、数据处理条款、验证码、付款或账户操作等按当前工具规则处理。只有确需本人完成/确认的节点才停；不要因每点一次继续就重新询问许可。
- 支持文件上传要有明确的文件范围和目标网站授权。默认不购买加急、贵宾、上传协助等附加服务。
- 真正的预约日期和分钟以最终摘要、账户预约记录及官方确认函为准，不能把“9:00”时段块解释成9点到场、9:30开始。
- 文件逐类添加成功后仍须执行最终保存。成功页和更新预约函列出的文件必须与本地清单一致，不能把“已选择文件”当作提交完成。

## 可重复运行的本地辅助工具

用 Python 3；PDF 检查脚本需要 pypdf。按当前环境定位运行库；缺依赖时使用可信包源。不要写死本机用户名或运行库路径。

检查明确指定的上传文件，默认要求小于5,000,000字节、无加密、英文文件名；实际网站限制优先：

    python scripts/preflight_pdfs.py --files /path/one.pdf /path/two.pdf --json-output /path/check.json

创建只含预约函和官方材料清单的打印包，原件字节不变；目的文件若内容不同则拒绝覆盖：

    python scripts/build_print_pack.py --appointment /path/confirmation.pdf --checklist /path/checklist.pdf --destination /path/Visa/To_Print

用户要求更新已有打印包时，先确认新材料已最终保存并下载新版官方预约函；将会被替换的旧打印件备份到 To_Print 之外，再运行脚本。清单未变就保留原版；上传受阻时不自行修改官方预约函或假称打印包已更新。

## 完成与可复用交付

- 报告哪些已准备、哪些实际提交、付款/预约/上传是否得到独立成功凭证，以及仍需核对的实际差异。
- 只在确认函或官方指引要求时添加打印内容；优先打印更新预约函及官方材料清单，另提醒携带护照原件。现场签名条目不要预签。
- 给出最终确认的日期、时间、完整中心地址和可打开的文件路径。不要保证获签、固定审理天数或当天结果。
- 用户资料、答案、密码、签名、截图、原件和申请编号只属于其申请工作目录；不得写回本技能或打进分享压缩包。
