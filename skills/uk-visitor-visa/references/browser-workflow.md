# UKVI 与 VFS 操作参考

## 连续填写的前提

按当前环境的浏览器/计算机工具文档进行 UI 操作，使用用户指定浏览器。浏览器步骤以实际页面为准；下列是路由，不是固定选择器或绕过接口。不要用脚本直调隐藏接口、读会话令牌或查看应用内部状态来代替可见流程。

维护申请专属的私密进度记录：当前阶段、已确认答案、待核实问题、已保存页面、付款/预约/上传结果和凭证文件。不要记录密码、OTP、支付资料、会话握手 URL 或认证令牌。

## 支付与提交前的人工核对

这是本项目对签证办理的操作要求，适用于每次支付、正式申请提交、声明接受、预约确认，以及材料最终上传、补交或替换。

1. 先完成可审阅版本，再停在最终动作前。展示实际页面或可打开文件，并集中列明本次动作、目标网站和申请、完整文件清单及版本、答案摘要及未解决差异；如涉及预约，列明中心、日期、时段、服务；如涉及支付，列明收款方、币种、总额及附加项目。
2. 要求申请人或其明确授权且有权核对的人工代表确认已检查上述具体内容，并明确授权列出的动作。未知必填事实不能靠概括授权补成答案。不得把沉默、超时、常见拟答、“一路办完”或对旧内容的确认当成本次人工核对。
3. 可一次确认同一份明确列出的材料和连续步骤，例如接受指定声明后递交当前版本；除当前工具要求逐次确认的动作外，不重复追问未变化的同批次内容。文件、答案、金额、服务、目的地或预约信息发生实质变化，重新展示变更并核对。新增付款或正式提交批次不能自动继承上一批确认。
4. 付款由本人在可信支付页面完成，不要求其在聊天中提供支付密码、验证码或完整支付凭据；若工具要求本人操作其他步骤，也进行交接。确认不等于支付成功或提交成功，动作完成后仍核对官方结果。
5. 在私人进度中记录已核对的动作范围、内容版本、确认时间和结果，不存认证秘密。普通读取、翻页和可编辑草稿保存可在既有授权范围内继续；平台若将“保存”视为正式递交，则按正式提交处理。

若网站选择文件后立即向服务器传输，须在选择文件前完成人工核对，不得以“还未点击最终 Save and Upload”为由提前传输未经本次核对的文件。

该要求通过技能指令执行；不得声称脚本或 README 能保证阻止任何第三方助手越过人工核对。

## UKVI

常见顺序为个人与联系信息、住址历史、证件、就业资金、旅行目的/住宿/同行、父母/家属、旅行史、移民史及品行安全题、核对答案、材料、声明、付款、后续动作。

名称顺序、关系类别和页面含义以帮助文字为准；例如“unmarried partner”不要只按中文“未婚”来勾选。用户的实际关系与表格分类分开核对。

批量取得安全题答案后，对照每页实质含义填写；问题范围更宽、增加题目或出现“是”的分支时再问。不能把一个总括“我没有违法”解释成所有历史、安全和职业问题均否。

先把完整申请和证据差异整理给用户核对。按工具规则在最终声明、条款和付款节点获得所需确认或交接。密码创建/变更与付款等由谁完成以本次工具规则为准；不要求用户把密码或银行卡密码发到聊天。

付款后下载官方申请表与材料清单，保留原字节，记录页数和申请编号。官方清单要求现场签名时不能套用用户的签名图预签。进入后续动作的“Provide documents and biometrics”链接转介至合作伙伴；不拼接认证链接。

区分完整官方申请表副本与材料清单：前者记录已提交答案，主要供核对留档；后者列明证据及到场要求。不要默认将申请表副本重复上传或加入打印包。若当前个性化清单另有明确要求则遵从；已上传一致副本时如实说明它是可省略的重复记录，不宣称所有申请都必传。

## VFS 预约

- 已付款先查现有预约和成功记录，尤其此前点击 Confirm 后报错时。
- 选用户实际可达的中心，区分同城普通和高端/其他分支。优先普通、免费预约及免费自行上传，除非用户指定并授权其他服务。
- “Standard Assisted”预约类型、收费的“Document Upload Assistance”和 UKVI priority service 含义不同，分别看价格与服务描述；名称里有 assisted 不能推断要收费或已购买材料扫描。
- 时间块、最早可用提示和最终分钟可能不同。核对最终摘要的日期、时间、地点及金额；最终确认函优先。
- 接受新条款、数据跨境处理或额外支出等按照本次工具规则确认。已经确认且没有实质变化的授权不要反复问。
- 确认后检查账户明确成功状态及预约函；仅勾选或加载动画不算成功。官方确认函下载、支付是否成功和预约是否成功是不同状态。

## 上传

1. 确认用户授权把具体准备材料上传到本次 VFS 申请。按页面检查文件格式、大小、数量、文件名和截止日期。
2. 先生成明确文件清单并检查原文与译文是否齐全。不要把整个文件夹自动上传。
3. 按页面举例分类：护照，资金，在职/赞助，家庭身份资料，其他说明，申请清单等；分类名称会变。
4. 按网站建议小批量、一次一个分类添加，等待每批结果；检查可见文件名。重试前先查是否已存在。
5. 每份材料可预览时核对预览；确认加密限制、页数和可读性。若页面错误地复用链接无障碍标签，用可见文件行和实际预览确认，不能依据旧标签判断上传对象。
6. 完成必须点击“Save and Upload”或该页实际最终按钮。成功页有明确结果后，再下载更新预约函，核对包含所有应提交文件；漏文件先补齐，不宣称完成。
7. 如页面提示关闭浏览器会丢进度，尽量一次会话完成；中断后先核对保存状态，不猜测草稿已提交。

## 已上传材料的替换与打印包更新

- 将当前已保存清单与本次变更分开记录：原文件、替换文件、额外新增文件、分类和最终保存状态。上传授权应覆盖这份具体变更，而不是整个本地文件夹。
- 替换前保留旧本地文件及旧确认函。先核对网站现存文件，避免登录恢复后重复添加；按网站提供的替换/删除流程处理指定旧件，遵守当前工具对删除操作的确认规则。
- 若已提交文件没有删除/替换操作，不反复尝试不存在的按钮。经授权补充内容一致的标注版或说明时，保留已提交旧版，如实报告“新增”及实际总数；不能声称旧件已被替换。需要正式撤回或更正错误事实时，另找官方更正渠道。
- 同一分类中的文件要逐项核对实际文件名。有的页面复用错误的 Preview/Delete 无障碍标签；这时使用可见文件行和截图确认对应关系，不凭过时标签删文件。
- 最终保存后核对成功页的完整集合：新版存在、被替换的旧版不再存在、其他材料未丢失；再下载官方更新预约函，核对文件名、申请编号、预约日期时间和地点。
- 只有确认函实际更新后才更新 To_Print 中的预约函；保留仍有效的官方材料清单，现场签名项留白。旧版本备份放在打印目录之外，以免全部打印时混入旧件。新旧官方 PDF 仅原字节复制，不自行编辑其中的材料列表。
- 登录失效或 429 发生在变更前时，原已保存集合仍是当前记录，新增材料标为“本地完成、未上传”，打印包标为“未更新”。若错误发生在保存之后，则先查真实保存结果，不推定全部成功或全部失败。

## 故障与重试边界

区分正在加载、验证码/登录失效、前端组件失败、权限错误、403201、429 与官方维护公告。记录用户可见提示和发生步骤，不记录认证数据。

有证据的修复可做一次，例如等待当前请求结束、一次普通刷新或通过官方转介重新进入。相同错误继续出现就停止该动作，给出准确的未完成状态与下一步，不连续点击、刷新、换入口反复提交。

提交/付款/预约超时后先查询结果，不重复产生副作用。必要时按文档读取控制台错误以判断页面组件失败；不把任意错误推断为服务端未收到请求。

429 只说明当前受到限制；不能据此认定检测到了 Computer Use，也不能承诺固定解封时间。遵守站点限制，不提供自动化伪装、轮换代理、绕验证码等规避办法。用户改用另一个浏览器后，应在其明确指定的浏览器中继续并先读现有记录。

成功交付要区分：UKVI已提交、用户已付款、VFS预约已确认、材料已最终保存、本人尚待到场、签证决定尚待作出。
